# 뉴스 수집기 기능 개발 워크플로우
뉴스 수집기 앱에서 새 기능을 개발할 때 브랜치 생성부터 커밋, main 병합, 요약까지 순서대로 진행합니다.
브랜치 이름 : $ARGUMENTS

## 실행 순서

### 1. 현재 상태 확인
- `git status`와 `git branch --show-current`로 현재 상태와 브랜치를 확인해.
- 현재 브랜치가 main이 아니라면 경고를 보여주고, main으로 이동할지 사용자에게 물어봐. 사용자가 동의하면 이동하고, 거절하면 여기서 중단해.
- 커밋되지 않은 변경 사항이 있어서 이동이 막히면 사용자에게 알려줘.

### 2. 새 브랜치 만들기
- `$ARGUMENTS`가 있으면 그 이름으로 브랜치를 만들어.
- `$ARGUMENTS`가 비어 있으면 어떤 기능을 개발할 것인지 물어보고, 답변을 바탕으로 영어 소문자-하이픈 형식(예: `add-category-filter`)의 브랜치 이름을 제안해. 사용자가 확인하면 그 이름으로 만들어.
- 이미 같은 이름의 브랜치가 있으면 사용자에게 알려주고 다른 이름을 물어봐.

### 3. 개발 시작 안내
- 브랜치 생성이 끝나면 '이제 개발을 시작해요!'라고 안내해.
- CLAUDE.md를 다시 읽고 이 프로젝트의 기술 스택과 컨벤션을 요약해서 알려줘. 최소한 다음을 포함해:
  - 기술 스택: Next.js(App Router, `src/app`), React, Tailwind v4, Clerk, Neon + Drizzle ORM, Claude API, Notion SDK
  - 컨벤션: import 별칭 `@/*` → `src/*`, UI 텍스트는 한국어, UI 작업 시 `ui.md` 준수, 요구사항은 `PRD.md` 기준
  - 주의: Next.js 16은 이전 버전과 다르므로 코드 작성 전 `node_modules/next/dist/docs/`를 참고

### 4. 완료 처리
- 사용자가 '완료' 또는 'done'이라고 입력하면 진행해. 그 전까지는 사용자의 개발 요청을 평소처럼 처리해.
- `git status`와 `git diff --stat`로 변경된 파일 목록을 보여줘.
- 변경 내용을 바탕으로 커밋 메시지를 자동으로 제안해. 최근 커밋처럼 한국어로 간결하게 쓰고, 시스템에서 안내한 Co-Authored-By 줄을 끝에 붙여.
- 사용자가 확인하면 변경 파일을 스테이징하고 커밋해. `.env` 등 비밀 정보 파일은 포함하지 마.
- 커밋 후 main으로 이동해서 작업 브랜치를 병합해(`git merge`). 충돌이 생기면 병합을 멈추고 사용자에게 알려줘.

### 5. 작업 요약
- 병합이 끝나면 다음을 요약해서 보여줘:
  - 브랜치 이름
  - 커밋 메시지와 변경된 파일 목록
  - 구현한 내용 요약
  - 병합 결과 (현재 브랜치: main)
